# UFO Hosting — Dashboard окупаемости рекламы

Веб-дашборд на Streamlit, который сопоставляет расходы на Яндекс.Директ с реальными оплатами клиентов и считает LTV, CAC, payback и когортный retention.

## Запуск

```bash
./run.sh
```

При первом запуске скрипт создаст виртуальное окружение `.venv/`, установит зависимости из `requirements.txt` и стартует Streamlit на `http://localhost:8520`. Дальше каждый запуск занимает 2–3 секунды.

Если хотите запустить на другом порту: `PORT=9000 ./run.sh`.

## Куда класть новые выгрузки

```
data/
├── orders/   ← CSV выгрузки заказов из админки UFO Hosting
└── ads/      ← XLSX-отчёты по рекламным кампаниям (Яндекс.Директ)
```

Складывайте файлы как есть, не переименовывайте — скрипт сам:

* подхватит все `*.csv` из `data/orders/` и дедуплицирует заказы по `ID покупки` (пересекающиеся периоды между выгрузками — это нормально, дубликаты убираются);
* подхватит все `*.xlsx` из `data/ads/` и разберёт каждый лист как отдельный месяц (русские названия типа «Апрель 2026» парсятся автоматически);
* устойчив к разной структуре листов рекламы (разные колонки в разные месяцы, несколько аккаунтов на одном листе — например, ноябрь 2025).

После добавления новых файлов: в правом верхнем меню Streamlit → **Clear cache** → перезагрузить страницу.

## Что показывает дашборд

| Вкладка | Что внутри |
|---|---|
| **Главные KPI** | Расход / доход / ROMI / CAC / LTV/CAC / ARPU / средний чек — только за перекрывающиеся месяцы (где есть И реклама, И платежи) |
| **📈 Динамика** | Помесячные графики: расход vs доход, новые клиенты, CAC, окупаемость M+0 |
| **🔥 Когорты** | Heatmap «когорта × месяц-смещение». Доход или retention. По месяцу регистрации или первой оплаты |
| **⏱ Окупаемость** | Когортный payback: CAC, накопленный доход, через сколько месяцев когорта окупилась |
| **🔁 Повторные оплаты** | Распределение клиентов по числу оплат, доля повторных vs новых |
| **📦 Продукты** | Доход по семействам (Naos, Haedus, Brachium, VPN, …) и по локациям (NL/DE/RU/FI/…) |
| **👥 Топ-клиенты** | Топ-N клиентов по сумме оплат: имя, дата регистрации, оплаты, стаж в днях |
| **📢 Кампании** | Расход по конкретным кампаниям Директа, динамика по месяцам |
| **🗂 Данные** | Сырые таблицы оплат и расходов с кнопкой выгрузки в CSV |

## Фильтры (сайдбар)

* **Период** — обрезает и платежи (по дате платежа), и расходы (по месяцу).
* **База когорты** — по месяцу регистрации (стандарт для хостинга) или по месяцу первой оплаты.
* **Атрибуция платного трафика** — слайдер 10–100%. По умолчанию 100% значит «весь доход приписываем Директу» (оптимистично). Если у вас есть оценка доли платного трафика — поставьте её, ROMI пересчитается.

## Ключевое ограничение

В выгрузках заказов **нет источника трафика** для каждого платежа (Yandex Direct vs SEO vs прямые заходы). Поэтому per-client атрибуция невозможна — мы сопоставляем агрегированно по месяцу. Чтобы получить честный per-client источник, нужна доработка GA4 (передача `purchase` события поштучно с `transaction_id`) — см. инструкцию от вашего аналитика.
