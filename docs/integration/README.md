# Сквозная аналитика UFO Hosting — план для BILLmanager 6

**Биллинг:** BILLmanager 6 от ISPsystem.

**Главное:** в BILLmanager 6 уже встроен модуль интеграции с Яндекс.Метрикой —
программировать ничего не надо. Нужно его включить, настроить цели в Метрике
и подключить Я.Директ. На это уходит **1-2 часа админа**, не программиста.

---

## Архитектура: что куда передаётся

```
[Сайт ufohosting.ru]           [Я.Метрика]              [Я.Директ]
    |                              ^                          ^
    | (Метрика уже стоит)          |                          |
    v                              |                          |
[Личный кабинет BILLmanager] ─────►| (визит + цели)           |
    | регистрация, оплата          |                          |
    | активация услуги             ├─ передаёт конверсии ────►| (автостратегии
    | и т.д.                       |  с реальным доходом       оптимизируются
                                                              на оплаты)
```

После настройки:
- В **Метрике** видна воронка: визит → регистрация → пополнение → оплата
- В **Я.Директе** → Мастер отчётов → метрика «Конверсии: <название цели>» +
  группировка по кампании/группе/ключу — реальный ROI per кампания
- **Автостратегии Я.Директа** начинают оптимизироваться на оплаты, а не на клики →
  CAC обычно падает в 2-3× за 1-2 месяца

## Что после настройки получим в нашем дашборде

**Сразу после включения модуля** (без доработок дашборда):
- Шапка дашборда продолжает показывать общий ROMI / CAC / LTV — как сейчас
- Главная аналитика per кампания и per ключ — **в Я.Директе и Метрике** (там
  цифры станут точнее благодаря офлайн-конверсиям)

**Если позже захотите видеть per-кампания ROMI прямо в нашем дашборде** —
добавляется отдельным шагом через **BILLmanager API**: дашборд тянет список
клиентов с их источниками регистрации напрямую из BILLmanager, без CSV.

Код для этого **уже заготовлен** в дашборде:
- [`src/data_loader.py`](../../src/data_loader.py) — парсит колонки
  `utm_source`/`utm_campaign`/`utm_term`/`metrika_client_id` если они есть
- [`src/metrics.py`](../../src/metrics.py) — функции `roi_by_campaign()`,
  `roi_by_keyword()` для расчёта ROMI по UTM

Активируется как только в выгрузке появятся эти поля (из BILLmanager API или
из Roistat-выгрузки).

## Альтернативный путь — полная сквозная аналитика через Roistat

Если хочется готовое решение «не настраивать цели руками, не строить дашборд» —
ISPsystem сами реализовали и описали такой кейс:

- [Habr: «Как внедрить сквозную аналитику и перестать гадать на кофейной гуще»](https://habr.com/ru/companies/ispsystem/articles/930836/) — кейс ISPsystem на их собственном BILLmanager
- Связка: BILLmanager + amoCRM + Roistat
- Результат у ISPsystem: CAC ↓40%, конверсия ↑25%, LTV ↑50%
- Минусы: Roistat платный (~5-10 тыс ₽/мес), нужен amoCRM

Рекомендация: сначала включить модуль Я.Метрики (бесплатно, 1-2 часа), посмотреть
результат месяц-два. Если данных не хватит — подключить Roistat.
